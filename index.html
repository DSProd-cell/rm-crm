Pipeline logic is read-only in v0. Changes go through engineering.
Boost STI
Entry Conditions
  • Lock-in done AND (App Ready date is null OR F2F not yet done)
Exit Conditions
  • App Ready date is set AND STI date is set
  • OR counselling_status = LS_LEAD_DROP_OFF
Boost Revenue
Entry Conditions
  • F2F attended = Present AND no lock-in (Prime/C2I) done yet
Exit Conditions
  • Any lock-in is done
  • OR counselling_status = LS_LEAD_DROP_OFF
Boost Loan
Entry Conditions
  • Lock-in done AND Loan VC not yet booked/joined
  • OR PF Log-in not yet done
Exit Conditions
  • Loan VC attended AND (IELTS_stage = IELTS_PAID_USER OR counselling_status in DEPOSIT_PAID / LS_LEAD_DROP_OFF)
Priority / Conflict Resolution
When a lead qualifies for multiple pipelines
  • Evaluation order: Boost Revenue → Boost Loan → Boost STI
  • Lead lands in the first matching pipeline
  • No lead sits in more than one pipeline at once
